# FeltLedger · 真实牌局记录与策略研究

[English](README.en.md) · 中文

这是用于**学术研究、规则验证与非金钱实验**的普通无限注德州扑克记录原型。现场每手重新洗牌、发牌；程序只记录看到的牌、各座位行动和最终分池，不代替现场发牌，也不提供充值、提现、现金兑换或牌局撮合。当前版本为本机单用户原型，Python 3.10+，无第三方依赖。

## 启动与使用

```powershell
python app.py
```

打开 <http://127.0.0.1:8765/>。程序只监听本机 `127.0.0.1`。

1. 设置 2–9 个座位、庄位、自己的座位、盲注和可选前注。填写**每人初始筹码**即可填入所有座位；若实际筹码不同，再逐座位修改。牌桌总筹码自动按各座位求和，开局时仍由规则引擎核对。
   每人初始筹码只是快捷填值；记录真实牌局时，各座位仍使用实际筹码，下一手继承结算后的余额。
2. 按现场顺序，给当前行动座位记录弃牌、过牌、跟注、加注到指定总额或全下。界面显示本街下注、底池、剩余筹码与合法加注范围。翻牌录入 3 张，转牌、河牌各录入 1 张。每街对手均可下注、跟注、加注或全下。
3. 只录入实际知道的底牌；未知牌保持 `??`。点击桌上的**对手名字**（如“对手5”），可从已有档案选择现实对手，或新建姓名、手动风格和备注。此座位从此手起关联该档案，下一手保留；在另一局遇到时，也可再次点击座位改为同一档案或修改风格。档案保存在本机。
4. 一人未弃牌时直接结束。摊牌时，若所有仍在局的底牌已知，可按牌型及边池自动结算；若有未知底牌，请手填**现场实际获奖金额**。手填金额仅核对总和，不验证各边池资格。
5. 点“下一手”归档本手，轮转庄位、重新收盲注，并清空底牌和公共牌；现场重新洗牌后继续录入。单步“撤销”仅用于当前手的最近一次牌局操作。

当前手和单步撤销保存在 `data/current_game.json`、`data/undo.json`；对手档案保存在 `data/profiles.json`；完成的手牌在点“下一手”时立即写入 `data/archive.sqlite3`。页面按 10 手一页读取归档摘要，点某手可查看事实行动和牌面。上述数据文件均被 Git 忽略。重设牌桌会覆盖尚未结束的当前手，界面会要求确认。

## 数据库与后续部署边界

当前存储分为三层：`game.py` 管规则、`policy.py` 只生成当前玩家可见的 `PolicyInput-v1`、`storage.py` 管归档。SQLite `hands` 表以 `hand_id` 去重，以递增 `sequence` 做游标分页，保存归档时间、人数、总筹码、结算方式与完整 JSON 快照。每手完成即用事务写入，不累积无界 JSONL 再一次性“打包”；SQLite 的 WAL 会自动检查点。未来离线训练可用 `storage.iter_hands(batch_size=...)` 分批读取，不必把全部手牌装入内存。

若旧版存在 `data/hands.jsonl`，启动时会逐行、每 100 手一个事务导入；成功后旧文件改名为 `hands.jsonl.migrated` 备份。导入中断可重试，手牌 ID 防止重复。迁移前应备份 `data/`。可用环境变量 `FELTLEDGER_DATA_DIR` 指定私有数据目录。

`GET /api/hands?limit=10&before=<sequence>` 返回分页摘要，`GET /api/hands/<hand_id>` 返回单手记录，`GET /api/game/observation` 返回版本化的当前决策观测（仅在轮到自己的座位时可用）。观测不含对手未知底牌或私人备注；后续模型只应接收此接口的数据。接口名称、金额单位（整数分）与输入输出版本见[模型方案](模型训练与数据适配方案.md)。

**当前服务仍只监听 `127.0.0.1`，没有账号、权限或多用户隔离，不能直接部署到公网。** 后续非本机部署应把 HTTP 层替换为有身份认证和用户／牌局隔离的服务，保留规则与观测契约；数据库可从本机 SQLite 迁到服务端数据库，并配备备份、访问审计和数据删除机制。性能目标需用真实样本量与并发量压测后确定。

托管版的数据库草案：`users(id)` 拥有 `sessions(id, owner_id, ruleset_version)` 和 `profiles(id, owner_id, ...)`；`hands(id, session_id, sequence, archived_at, summary, snapshot_json)` 按所属会话分页查询，并对 `(session_id, id)` 唯一约束。只有当训练查询需要逐动作检索时，再从快照派生 `hand_actions(hand_id, ordinal, street, seat, action, amount_cents)`。迁移时保留原始快照、规则版本与来源，避免把现在的单用户 ID 当作跨用户唯一身份。

## 与标准牌局流程核对

| 现场步骤 | 本版处理 |
|---|---|
| 每手洗牌、两张底牌、收盲注／前注 | 现场发牌；程序收盲注／前注并记录已知底牌，双人桌庄家为小盲 |
| 翻前行动 | 大盲左侧先行动；双人桌庄家先行动 |
| 翻牌、转牌、河牌 | 分别录入 3、1、1 张；每街由庄家左侧仍可行动者先行动 |
| 下注选择 | 按顺序记录弃牌、过牌、跟注、加注到指定额、全下；校验最小加注、短额全下后的加注权 |
| 无人跟注、弃牌获胜、摊牌 | 退回未被跟注额；支持弃牌获胜、牌型比较、平分、边池和现场手填获奖额 |
| 下一手 | 按仍有筹码的座位轮庄，现场重新洗牌，清空上一手的牌 |

规则依据：[PokerStars 德州扑克规则](https://www.pokerstars.com/poker/games/rules/)、[PokerStars 下注、全下与边池说明](https://www.pokerstars.com/help/articles/poker-rules-master/229146/)。这是普通无限注桌的 MVP；抽水、straddle、保险、跑多次公共牌、鱿鱼特殊规则和现场买入／离桌后重组座位仍需另行定义。

## 事实、估算与模型性能

训练输入／输出规则、无监督学习的适用范围、公开数据与框架调研、对抗式自博弈路线和分阶段成本，见 [模型训练与数据适配方案](模型训练与数据适配方案.md)。该文件是持续更新的研究基准；当前没有启动训练。

- **事实**：现场输入的牌和行动，以及程序据此计算的底池、筹码、合法动作、已知最佳五张牌。输入有误时，这些显示也会有误；请对照现场核对。
- **估算**：轮到自己且已知两张底牌时，可查看 1500 次随机未知对手手牌的摊牌胜率、抽样区间和简化跟注期望。手动对手风格只微调建议阈值，未建立该对手的真实手牌范围。
- **未评测**：策略建议准确率、真实行动 EV、盈利能力、市场竞品水平。抽样区间反映随机模拟误差，不代表决策准确率。当前建议不是已训练 RL 或 GTO 策略。

达到可比较的模型性能时，应固定规则、盲注、筹码深度、对手池和验证种子；用独立盲测比较每百手收益、置信区间、决策延迟与模型版本，再逐步加入位置、行动线、有效筹码及对手范围。当前程序保留 `poker.advise()` 作为策略替换入口。

## 验证

```powershell
python -m unittest discover -s tests -v
```

测试覆盖常用牌型、双人桌顺序、各街下注、短额全下、边池、重复牌、总筹码校验及跨手对手档案复用。真实牌局仍需逐手对照现场核验。
